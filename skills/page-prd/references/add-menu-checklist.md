# 迭代操作清单：给已有原型加菜单 / 加功能

> 默认原则：用户没说新建 → 在**已有的那一份 index.html** 上追加。以下每一步默认都是「加法」：用户没有明确要求时不删除、不重写已有内容；用户要求的删改（如删字段、删列表列）照做，并写进更新摘要。
> 说明结构为 **v3.0 两章式**：一、页面概述（菜单位置 / 解决问题 / 权限说明表）｜二、功能说明（按功能点逐个展开）。
> **工具条 5 个按钮**：编辑需求说明 ｜ 新增章节 ｜ 导出 HTML ｜ 导出给 AI ｜ 恢复默认。没有「导出 Markdown」按钮，需要 md 时由 Agent 跑 `edit-spec.js --to-md` 生成，**不要在页面上加该按钮**。
> **界面样式**：左侧一律用模板里的 HeroUI 组件（`<hui-select>`、`<hui-checkbox>`、`<hui-modal>` 等）和 HeroUI 类名、主题工具类，图标用 `<lc-icon>`，写法见 `prototype-spec.md` 第六章；不写原生下拉框、复选框，不写死颜色和 11px / 12px 字号，不用 emoji 当图标。

## 0. 总原则：原型动了，说明必须跟着动（v3.7）

**左侧原型有任何增删改，右侧说明必须在同一次交付里同步更新**——交付一个「原型变了但说明没跟」的原型 = 半成品。

**对照表（改完左侧，照着这张表逐项补右侧）**

| 左侧原型改了什么 | 右侧说明要同步改什么 |
|---|---|
| 新增菜单 | 加一个 `.menu-pane`（页面概述 + 权限表 + 各功能点卡片），编号从 ① 重排 |
| 菜单内新增页面 / 弹窗 / 按钮（= 新功能点） | 权限说明表加一行（功能点列 lock）+ 功能说明加一张卡片，编号顺延 + 左侧气泡挂新编号 |
| 表单加 / 删字段 | 该功能点「字段说明」表增删行（元素、类型列 lock，其余按新增/编辑类规则） |
| 列表加 / 删列 | 「列表字段」表增删行（元素列 lock） |
| 新增状态 / 加了状态流转入口 | 「状态流转」由留空改为填写 + 「列表字段」操作列备注更新（各状态展示哪些按钮） |
| 交互形态变了（弹窗 ↔ 独立页面） | 该功能点「交互」子项改写，写明是页面还是弹窗 |
| 新增 / 改筛选条件、排序 | 「交互」补筛选描述 + 「数据排序规则」同步 |
| 改了 mock 数据的展示方式 | 对应「展示逻辑说明」列同步 |

**改完必换 `PROTO_KEY`**。改完按 F 节给出「说明更新摘要」。

## A. 新增一个菜单（最常见）

按顺序做 5 步，缺一不可：

1. **nav 加菜单项**（同分组内放末尾）
   ```html
   <div @click="switchMenu('order')" :class="navCls(menu==='order')"><lc-icon name="file-text"></lc-icon>订单管理</div>
   ```
   未实现的菜单保持置灰 + toast「该菜单暂无原型，需求评审后再补」，不要隐藏。

2. **Vue state 加该菜单的独立状态**
   `views` 加 `order:'list'`；筛选 `oq`、数据 `orders`、过滤 `orderFiltered`、当前行 `orderCur`、表单 `orderForm`、错误 `orderErr` 各自独立命名，**不要复用别的菜单的变量**。行内更多菜单用 `<hui-menu>`，自己管开关，不需要行菜单 id。

3. **内容区加列表页 / 详情页**
   `<div v-else-if="menu==='order' && views.order==='list'">…</div>`，放在现有菜单块的后面。字段分组卡片、弹窗按规范 2.4 / 2.5 做，组件写法照规范第六章。

4. **`#specBody` 末尾追加说明 pane**
   ```html
   <div class="menu-pane hidden" data-menu="order" data-label="订单管理"> …两章… </div>
   ```
   - 初始加 `hidden`（除非它是默认打开的第一个菜单）
   - **一、页面概述**：菜单位置 → 解决问题 → 权限说明表（每行一个功能点；第 1 列 `class="lock"` 不可改，操作权限/数据权限/备注三列 `data-edit` **且初始必须留空，不得预填角色/数据口径**）
   - **二、功能说明**：每个功能点一张 `<div class="fn item" data-k="①" onclick="flashAllNoScroll('①')">`（点卡片不滚动；合并脚本的安全检查也只认这个写法），卡内按类型放子项（**卡片不显示类型标签**，类型只决定子项结构）：
     - 列表类：交互 → 状态流转（无流转留空）→ 列表字段表（元素 lock / 展示逻辑说明 / 备注）→ 数据排序规则
     - 表单类：交互（写明页面 or 弹窗）→ 字段说明表（**新增类**：仅备注 `data-edit` 其余 lock；**编辑类**：必填/校验规则/默认值/备注四列 `data-edit`，仅元素与类型 lock）→ 业务规则说明（`.sub-v.rules`，分条圆点展示）
     - 详情类：交互 → 展示元素说明表（分组/字段名 lock，展示逻辑说明/备注可改）
     - 可视化类：交互 → 数据逻辑（写清每个指标计算公式，不确定留空）
     - 其他类：交互 → 业务规则说明（`.sub-v.rules` 分条，多条规则一条一个 `<div data-edit>`）
   - 子项结构固定：`<div class="sub"><div class="sub-k">子项名</div><div class="sub-v" data-edit>内容</div></div>`

5. **编号规则**
   - 编号单位 = **功能点**，新菜单内独立从 ① 开始
   - 左侧气泡：`<span class="num-badge" data-k="①" @click.stop="focusNum('①')">①</span>`（父元素要 `relative`）；行内更多菜单的项在 `<hui-menu>` 的 items 里写 `k:'①'`，会显示成 `num-badge-in`。不能用 `badge` 类名，HeroUI 有同名组件类
   - 同一功能点的多个入口挂同一编号（列表类的筛选卡 + 分页器都是 ①；详情页右上「编辑」与行内「编辑」都是同一号）
   - 换 `PROTO_KEY`（说明结构/内容变了，旧缓存必须失效）

## B. 已有菜单加功能（加一个页面/弹窗/字段）

- 左侧加页面/弹窗，右侧在**该菜单的 pane 内**补：
  - **权限说明表加一行**（功能点列 `class="lock"`，其余三列 `data-edit`）
  - **二、功能说明加一张功能点卡片**，编号顺延
- 已有功能点补规则：直接在该卡片的子项里加 `<div data-edit>`（业务规则支持多行）
- 编号顺延后检查左侧气泡是否同步新增

## C. 收尾自检（必跑）

**迭代前先做一件事（对应 SKILL.md 的「场景 B」）**：如果用户提过"我在浏览器里改过说明"，或给了导出文件路径，先跑「D. 人工修改回传」合并进来，再开始本次追加。否则你的改动会在用户下次导出时被冲掉。

```bash
node "<skill>/scripts/edit-spec.js" <index.html> --check
```

`--check` 自动检查：`data-module` 已填且不是模板占位、`data-active-menu` 指向存在的 pane、`protoTpl`、`PROTO_KEY` 已换成真实值、`fileStamp`、导出基线逻辑、结尾 `</html>`、没有「导出 Markdown」按钮、没有残留的 `★` 占位、左侧 `switchMenu('xxx')` 的每个菜单都有对应 `.menu-pane`、每个菜单的权限说明表功能点 = 功能点卡片名称（一一对应）、卡片没有类型标签、CDN 带版本号、加载了 HeroUI 样式、Tailwind 用 v4 浏览器版、没有用 emoji 当图标、左侧原型没有原生下拉框 / 复选框 / 单选框、编号气泡用 `num-badge`、工具条有「导出给 AI」、不存在 document 级 `.item` 点击监听。退出码非 0 时按输出修好再跑。

另需人工确认：
- [ ] 需求里**没提**的功能没被做进去（尤其是删除、导入导出、批量操作）
- [ ] 需求没提的状态流转 / 数据权限口径 → 对应条目**留空**，不要编造
- [ ] **权限说明表第 2/3/4 列全部为空**（`<td data-edit></td>`）——出现过任何角色名就是违规
- [ ] **状态流转说明为空**，除非原型里真的有状态变更入口（按钮/下拉/流转申请）
- [ ] 功能点卡片上**没有类型标签**（无 `fn-type`）
- [ ] 所有「业务规则」都是分条圆点展示（`sub-v rules`），没有一段话的
- [ ] 顶部提示框是 HeroUI 警示提示条（`alert alert--warning`），分行展示，第 3 行是「点编号气泡后可定位到具体的功能描述…是功能编号」
- [ ] 左侧的颜色、圆角、阴影都来自 HeroUI 类名和主题工具类（`bg-surface`、`text-muted`、`shadow-surface` 等），没有 `bg-slate-*`、`#2563EB` 这类写死的颜色和 `text-[11px]`、`text-[12px]`
- [ ] **工具条在底部**：`<div id="toolbar" class="sticky bottom-0 …">` 位于 `</aside>` 之前且**在 `#specBody` 之外**（在里面会被存进缓存导致重复渲染）
- [ ] 编号联动：左侧气泡点得动 → 右侧平滑滚动到对应功能点卡片；右侧卡片 `onclick` 是 `flashAllNoScroll`（不滚动）
- [ ] 「导出给 AI」弹窗打开后，提示词里有每个菜单的每个功能点，留空项写成「未提供，需确认」
- [ ] **说明显隐开关**：`<div id="protoWrap" class="relative shrink-0">` 包住 `#app`（`#app` 上**不再有** `w-[62%]`）；`#specToggle` 在 protoWrap 内、app 之后；分割线 `id="specDivider"`、aside `id="specAside"`；CSS 有 `#protoWrap{width:62%}` 与 `body[data-spec="hidden"] #protoWrap{width:100%}`
- [ ] `flashAll` 开头有「隐藏态自动展开」；`initSpecHidden()` 已调用；`<body>` 上有 `data-spec`
- [ ] 编辑类表单字段表：必填/校验规则/默认值三列表头为 ✏、单元格为 `data-edit`；新增类表单仍全锁
- [ ] `onEdit` 会给被编辑的 `[data-edit]` 打 `data-user-edited="1"`；`addSection` 新建章节整块打标
- [ ] **本次没有覆盖任何带 `data-user-edited` 标记的内容**（有冲突要停下来问用户）
- [ ] 若走的是场景 C（对话改说明）：`--bump-key` 在改内容**之前**跑过，`--verify` 退出码为 0（原型未动 / 锁定内容未变 / 未覆盖用户定稿）
- [ ] mock 数据 ≥8 条，是贴近真实格式的虚构中文业务数据（不用真实企业名称和真实手机号）
- [ ] 新菜单的 mock 编号前缀不与其它菜单冲突
- [ ] 锁定列都没有 `data-edit`（`<td class="lock">`）

## D. 人工修改回传（SKILL.md 的「场景 B」，独立触发，不是迭代的前置步骤）

> **这一步严禁改用「重新生成原型」来代替** —— 重生成会把用户改的说明整块冲掉。只能跑脚本合并。

```bash
# 1) 先干跑
node "<skill 目录>/scripts/merge-spec.js" <用户导出的 html> <目标 index.html> --dry-run
# 2) 确认报告无异常后，去掉 --dry-run 正式合并
node "<skill 目录>/scripts/merge-spec.js" <用户导出的 html> <目标 index.html>
```

- 脚本只替换 `#specBody`，**左侧原型一字不动**；会自动备份到 `_archive/`、换新 `PROTO_KEY`
- 报 `[中止]` 时**不要直接加 `--force`**，按 `SKILL.md`「人工修改回传流程」里对应的中止原因处理
- 合并完成后读报告里的「人工定稿标记」数量，向用户复述本次保留了哪些他的改动

## E. 对话修改需求说明（场景 C，v3.6）

> 用户直接说"帮我改下需求说明里的 xxx"。**默认只改说明，原型不动。**

步骤和一致性判定表以 `SKILL.md`「对话修改需求说明流程（场景 C）」为准：冲突预检 → `--list` 定位 → 一致性判定（命中 ✅ 先问用户）→ **改内容之前**跑 `--bump-key` → 精改 `#specBody`（只动 `<div class="sub-v">` / `<td>`，改的单元格加 `data-agent-edited="1"`）→ `--verify`。

**红线**：
- 目标单元格已有 `data-user-edited` → 不许覆盖，把冲突点列给用户决定
- 不许碰 `protoTpl` / `#app` / 任何 `<script>`（除 PROTO_KEY 那一行）
- 改完必换 key（`--bump-key` 已代劳）；刷新页面才看得到

## F. 交付前

- 运行环境有浏览器自动化工具（如 Playwright MCP）时，自己打开 index.html，用 DOM 快照走一遍：菜单切换 → 右侧说明跟着切 → 编号双向定位 → 编辑说明（确认锁定列没有 `contenteditable`）→ 导出文件名带时间戳；没有这类工具时，把这几项列给用户，请他打开页面检查
- 给出 index.html 的绝对路径
- 告诉用户：哪些是按需求做的，哪些没做（因为需求没提），避免误判为遗漏

### 必给「本次需求说明更新摘要」（v3.7）

**凡是动过左侧原型，交付时必须概括说明右侧需求说明改了哪些内容**——概括即可，不用逐字复述。格式：

```
本次需求说明同步更新：
- 客户管理：新增「批量导入」功能点（编号 ⑤）+ 权限表加一行
- 客户列表：字段表新增「客户等级」列；状态流转补充「已流失」
- 客户详情：交互由页面改为弹窗
- 左侧原型同步改动：列表右上新增「批量导入」按钮、状态标签新增「已流失」
- 待你补充：新增功能点的操作权限 / 数据权限 / 备注三列仍为空
```

要点：
- **按菜单分组**，每条一句话说清"哪个功能点改了什么"
- 左侧原型改了什么也要单列一条（让用户一眼看出两者对应关系）
- 新增内容里**留空待填的项要提醒**（权限三列、状态流转、公式）
- 只改说明没动原型时（场景 C）同样给摘要，并明确说"原型未改动"
