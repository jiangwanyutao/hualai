# 规范版本变更记录

执行 skill 时不需要读本文件。

> v4.1 变更（2026-10-22，界面改用 HeroUI 样式）：①组件外观改为加载 HeroUI v3 官方编译样式 `@heroui/styles@3.2.6/dist/heroui.min.css`，Tailwind 由 v3 网页版换成 v4 浏览器版（只负责布局），保留 Vue 3 单文件、双击打开；②模板封装 `hui-select`、`hui-checkbox`、`hui-radio-group`、`hui-tabs`、`hui-modal`、`hui-drawer`、`hui-menu`、`hui-search`，状态属性按 HeroUI 的要求设置（弹窗、抽屉的 `data-placement` 写在 container 和 dialog 上，补 `--visual-viewport-height`）；③去掉商务蓝配色和写死的 11px / 12px 字号，颜色、圆角、阴影、字号改用 HeroUI 主题变量，规范第六章改为「界面样式：HeroUI 组件 + lucide 图标」；④图标改为 lucide 1.60.0 内联 SVG（`ICONS` + `<lc-icon>`），去掉 emoji 图标；⑤编号气泡类名改为 `num-badge`，避开 HeroUI 的 `badge`；⑥新增「导出给 AI」：工具条按钮打开弹窗，从说明区生成给 Claude Code / Codex 的提示词，空项写「未提供，需确认」，可复制、可下载 `.md`；⑦`--check` 新增 HeroUI 样式、Tailwind v4、emoji 图标、原生控件、`badge` 类名、导出给 AI 六项检查；⑧清单里功能点卡片的点击写法改为 `flashAllNoScroll`，与模板和合并脚本的安全白名单一致。
> v4.0 变更（2026-10-22，按审阅意见修订）：①skill 名称改为 `page-prd`（目录同步改名）；②原型目录改为用户指定、默认 `<当前工作目录>/prototypes/`，去掉写死的本机目录；③交付改为给出绝对路径，不依赖 `present_files`；④收窄 description 中场景 C、D 的触发说法，场景 B 只认导出格式文件名或明确的浏览器改动回传；⑤场景 C 步骤改为「定位 → 判定 → `--bump-key` → 改内容 → `--verify`」，脚本提示同步；⑥`--verify` 只拿 `--bump-key` 的备份当基线；⑦导出 HTML 写入 `data-base-key`，合并时检测目标文件在导出之后是否被改过，并列出会被冲掉的 Agent 改写；⑧合并前拒绝带脚本或未知事件属性的导出文件；⑨模板去掉 document 级 `.item` 点击监听（点卡片不再滚动）、删除无入口的 `addItem` / `delItem` / `addTableSection`，补编辑类、可视化类、其他类示例；⑩CDN 固定版本；⑪mock 数据改为虚构；⑫`edit-spec.js` 新增 `--check` 自检、`--norm` 先备份、`_archive/` 每类备份只留最近 20 份；⑬版本记录从规范正文移到本文件。
> v3.9 变更（把「导出 Markdown」补成**独立触发场景 D**）：①v3.8 删了按钮却没把「用户要 md」补进触发场景，导致用户说「把需求说明导出成 Markdown」时可能识别不到本 skill；②触发表新增场景 D，与场景 C 明确区分（C 改内容 / D 只导出副本）；③SKILL.md `description` 扩为四类场景、新增「导出需求说明 Markdown（场景 D）」章节、判定顺序更新；④spec 新增「七·补5」含输出规格；⑤**冲突预检**写为强制步骤——脚本读磁盘文件，读不到浏览器缓存，用户在浏览器改过说明必须先走 B 合并再导出，否则 md 会缺内容。
> v3.8 变更（**删除「导出 Markdown」按钮，改为 Agent 侧生成**）：①工具条按钮由 5 个精简为 4 个（编辑需求说明 ｜ + 新增章节 ｜ 导出 HTML ｜ 恢复默认）；②`_subMd` / `exportMd` 两个函数从页面彻底移除（`index.html` 与 `assets/template.html` 已同步），**不许再加回来**；③`edit-spec.js` 新增 `--to-md`，需要 md 时由 Agent 直接生成（输出 `<模块名>-需求说明-<时间戳>.md`，内容与原先按钮导出一致）；④删除理由已写进规范：md 只出不进、不在回传主链路、且会让人误以为它也能回传。
> v3.7 变更（补齐「优化需求时说明同步 + 交付反馈」）：①第四章硬约束新增第 7 条——**原型动了，说明必须跟着动**，禁止交付"原型变了但说明没跟"的半成品；②交付必须附**概括性的「本次需求说明更新摘要」**（按菜单分组、每条一句话 + 单列左侧原型改动 + 提醒留空待填项）；③`add-menu-checklist.md` 新增第 0 节「原型改动 → 说明同步对照表」（8 类原型改动对应该补哪些说明）+ F 节摘要格式示例；④SKILL.md 执行流程第 3/5 步同步 + 新增红线第 11 条（顺带修正红线标题"七条"与实际条数不符）。
> v3.6 变更（新增**场景 C：对话式修改需求说明**）：①触发场景由两类扩为**三类**（A 生成/迭代、B 人工修改回传、C 对话改说明）；②确立**默认只改右侧说明、左侧原型不动**，改动命中「一致性判定表」✅ 项时必须先问用户是否同步改原型；③新增 `data-agent-edited="1"` Agent 改写标记（与 `data-user-edited` 区分，冲突时以用户为准）；④新增 `scripts/edit-spec.js`（`--list` 定位 / `--bump-key` 备份+换 key / `--verify` 校验原型零改动与锁定内容 / `--norm` CRLF 归一化）；⑤SKILL.md 新增第 10 条红线。
> v3.5 变更：新增**需求说明显隐开关**——左侧原型区右下角一个悬浮按钮，点一下隐藏右侧说明（左侧铺满全屏）、再点一下恢复。状态存 `<body data-spec>` + localStorage，导出文件保持导出时的状态；点编号气泡时若说明处于隐藏态会自动展开（详见「七·补3」）。
> v3.4 变更（用户要求"必须在 skill 触发场景中记录回传这个场景"）：①第一章改为「定位与触发场景」，明确**两类触发场景**——A 生成/迭代原型、B 人工修改回传；②列出场景 B 的三个识别信号与「拿不准就问」话术；③明确**场景 B 严禁重新生成原型**（会把用户改的说明整块冲掉）；④场景 B 必须写进 SKILL.md 的 frontmatter `description`，否则不会被识别。
> v3.3 变更（解决「用户改的说明 Agent 看不到」的断层，确立**方案 A 导出回传**）：①明确断层真因是**双写不同源**（磁盘 index.html vs 浏览器缓存），浏览器 `file://` 对磁盘只读是硬边界；②新增 `data-user-edited` **人工定稿标记**（`onEdit` 打标 + `addSection` 整块打标），Agent 后续迭代**不得覆盖**带标记的内容；③新增 `scripts/merge-spec.js` 合并脚本（缺失检查 / 自动备份 / 只换 `#specBody` / 换 key / 差异报告）；④顶部提示框新增第 5 行提醒导出回传；⑤SKILL.md 新增「人工修改回传流程」章节与第 9 条红线。
> v3.2 变更（用户验收 v3.1 后提出 3 项）：①顶部工具条**移到右侧说明区底部吸附**（`sticky bottom-0`，置于 `</aside>` 前、`#specBody` 之后）；②顶部提示第 3 行改为「点编号气泡后可定位到具体的功能描述，编号不是具体的功能需求，是功能编号」；③点左侧编号气泡时，右侧说明**平滑滚动定位**到对应功能点卡片（`scrollIntoView({behavior:'smooth',block:'center'})`）。
